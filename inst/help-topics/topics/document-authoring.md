# Writing R Markdown and knitr documents

The **Script** tab can hold a plain R script or an R Markdown/knitr document.
The mode selector at the top switches between them:

| Mode | File | Commands generated by the dialogs |
|---|---|---|
| R script | `.R` | appended as plain lines |
| R Markdown | `.Rmd` | appended as R code chunks |
| knitr | `.Rnw` | appended as knitr chunks |

Switching mode converts the buffer without losing code: R to Rmd wraps the
script in a chunk, Rmd to R extracts the chunk code, and Rmd to Rnw converts
the chunk markers.  Converting between R Markdown and knitr keeps the code
chunks and uses the target template; prose is not translated between the two
markup languages.  A generated chunk looks like this:

```r
summary(mtcars)
```

## Start a document

- **File > New R Markdown document...** creates a template with YAML front
  matter and an `## Analysis` heading.
- **File > New knitr document...** creates a LaTeX template.
- **File > Open R Markdown file...** loads an existing `.Rmd` or `.md`.
- **File > Open knitr file...** loads an existing `.Rnw`.

The **New**, **Open** and **Save** buttons in the Script tab do the same.

## Chunks and sections

Every dialog you use appends its commands as a chunk.  The **Section** button
(or **Edit > Insert section**) adds a Markdown heading; the level selects
`#`, `##` or `###`.

**Edit > Remove last Markdown command block** removes the last chunk.
**Edit > Remove last Markdown section title** removes the last heading.

A chunk is recognised only when its fences are complete, so prose that looks
like code is never removed by mistake.

**Insert chunk** (the **Chunk** button or **Edit > Insert chunk...**) creates a
chunk with common options:

```r
plot(mtcars$mpg)
```

with a chunk header such as `r, fig.width=6, fig.height=4, echo=FALSE`.
The label is optional; the echo, warning and message switches control what
appears in the knitted document.

## Bibliography

**File > Document bibliography...** adds a `.bib` file to the YAML front
matter:

```yaml
---
title: "RcmdrShiny report"
bibliography: "references.bib"
---
```

Citations then use Pandoc syntax, for example `[@fox2016]`, and a
`references` section is added automatically at the end of the document.

## Knit the document

**File > Knit document...** or the **Knit** button opens a small dialog:

| Format | Requirements |
|---|---|
| HTML | `rmarkdown`, `knitr`, Pandoc |
| PDF | the above plus LaTeX (`pdflatex`) |
| Word | `rmarkdown`, `knitr`, Pandoc |

The output opens in the **Report** tab and can be downloaded from there.  The
document is evaluated in the current session, so it sees the active data set
and models.

```r
# What the Knit button runs, in essence:
rmarkdown::render("document.Rmd", envir = state$env)
```

A knitr document is converted with `knitr::knit()` and then `pdflatex`.

## Requirements

```r
install.packages(c("rmarkdown", "knitr"))
```

Pandoc ships with RStudio and with recent R installations; otherwise install
it from <https://pandoc.org/>.  For PDF, install a LaTeX distribution
(for example TinyTeX).

## Security

Knitting **executes the code in the document**.  Use it only on documents you
wrote or trust, exactly as you would with Rcmdr or `rmarkdown::render()`.
