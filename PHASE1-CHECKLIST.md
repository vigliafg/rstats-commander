## Architecture notes

- Menu status is computed per render from `activation` and `install`
  expressions in `Rcmdr-menus.txt`; `"hidden"`, `"porting"`, `"inactive"` and
  `"enabled"` are the four states.
- Dialog command execution goes through `apply_dialog_result()`; commands are
  still generated by pure builders, which remain the parity contract.
- The data editor writes back through `update_dataset()`; the dataset cell
  threshold is an option and is validated in the Options dialog.
- Plot files are copied into a per-session directory served with
  `addResourcePath()`, so the gallery works without embedding base64 data.
- `rgl` is optional: the 3D pane appears only when the package is installed.

## Known limits (accepted for Phase 1)

- R Markdown/knitr document generation is still disabled; the menu entries are
  hidden until the corresponding infrastructure is ported (later phase).
- Only the first data frame in an RData file is activated; multiple data
  frames require an explicit selection dialog (Phase 2).
- The Tk compatibility shim mentioned in the plan is intentionally deferred:
  new dialogs are written directly against the Shiny widget library, which is
  shorter and testable.  The shim will be added only if an existing dialog
  cannot be ported economically without it.
- Language switching requires restarting the session because gettext loads
  the catalogue at process start.
- Interactive editing uses `hot_to_r()` whole-table changes; large data sets
  are view-only above the threshold.
- `identify()`/`locator()` and plugin dialogs remain out of scope.
